# P4 原操作查询与恢复

已实现客户端观察状态与后端业务状态分离。`Conversation.result` 是当前展示结果，`backend_result` 是最后一次校验通过的业务结果；`needs_reconciliation` 表示客户端需要查询。通信异常不会把后端成功改成失败，也不会将客户端 unknown 写回数据库。

`recover()` 查询当前请求的原动作/幂等键；`recover(action=..., idempotency_key=...)` 用于重启后选择原操作。查询校验原请求、关联编号、操作键和内容摘要，再恢复原挑战或结果。已有业务状态仍执行迁移检查；客户端 unknown 不冒充后端状态参与迁移。

`BankGateway.list_operations(principal_id=...)` 是可信页面内部索引，不注册为模型动作。只返回该身份的动作、键、状态，包含全部待处理操作及最近 20 条终态。会话启动时发现未决操作，会阻止新转账并要求先恢复；不会自动确认。当前未决操作也不能通过切换历史记录绕过。

找不到原操作、查询失败、坏回执或内容不匹配时保留原键、显示待核实、禁止重复发起。模拟凭证签发失败和错误凭证同样先核实原操作，不把一次授权错误当成业务终态。

阶段验收：13 项新增恢复测试及原有 144 项全部通过，共 157 项，0 跳过。覆盖初始回执丢失、扣款回执丢失、重启发现待办、终态恢复、错误内容、过期、错误凭证、跨身份索引、旧待办不被最近记录挤掉、未知结果持续阻塞等。
