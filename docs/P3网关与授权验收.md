# P3 持久化网关与授权验收

> 阶段历史记录：下文描述该阶段验收时的实现。当前 P0—P6 已完成，页面已接入持久化模拟账本；最新启动和行为请以 [A 第二轮使用与验收](A第二轮使用与验收.md) 和 [当前验收记录](A第二轮验收记录.md) 为准。

本阶段接通公开转账网关与 P2 模拟资金服务。所有资金都是本地虚构余额，身份来自可信演示调用方，`demo_otp` 是模拟验证，不是短信、银行认证或真实支付。页面仍使用第一轮测试替身；P4 负责客户端恢复，P5 再接入页面。

## 快速复现

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m examples.gateway_demo
.\.venv\Scripts\python.exe -B -X utf8 -m unittest tests.test_gateway -v
```

演示每次新建临时库，结束后清理，不修改 `runtime/sandbox.sqlite3`。第一笔 200 元需要普通确认，第二笔 900 元使日累计达到 1100 元，需要模拟强验证。完成后 A 900 元、李明 1100 元，共两筆业务、四条流水；重复授权返回原结果。演示不打印凭证明文。

## 调用约定

| 入口 | 输入与行为 |
|---|---|
| `BankGateway(store, clock=...)` | 时钟仅用于可信测试注入，默认使用当前 UTC 时间；不接收用户自报累计 |
| `get_context(principal_id=...)` | 返回当前身份的可信资源快照 |
| `execute(request, principal_id=...)` | 校验 v1.1；转账先持久化原请求和确认/验证挑战；此时不动资金 |
| `authorize(payload, principal_id=...)` | 只接收挑战、操作摘要、决定及可选凭证；读取保存的原请求，不接收替换金额/对象 |
| `issue_demo_proof(challenge_id, principal_id=...)` | 仅演示服务端调用，不注册为模型工具；返回随机凭证，库中只存 SHA-256 摘要 |
| `execute(operation.get, principal_id=...)` | 查询当前用户的原操作；外层查询成功不代表内层转账成功 |

`execute` 重放的响应关联本次 request_id/trace_id，保存的原请求不变。`authorize` 的响应始终关联保存的原请求。成功来源为 `sandbox`，待确认/待验证来源为 `gateway`。共享字段、26 个动作和 JSON v1.1 均未修改；当前仅开放普通转账及原有四个查询，预算/调度等其他写动作仍未实现。

## 授权与安全口径

- 原操作由“用户 + 动作 + 幂等键”唯一标识；同键修改内容会被拒绝。完成后的合法重试只返回原结果。
- 每个挑战有效期 10 分钟。到期瞬间即失效；授权返回 `failed / AUTH_EXPIRED`，原键不续期，新操作需要新键重新确认。执行入口重放尚未处理的过期挑战也不会续期，最终授权或取演示凭证时判定过期。
- 收款账户在创建挑战时绑定；确认前若可信收款人映射改变或旧挑战没有绑定，结束本次操作并要求重新发起，不悄悄改收款账户。
- 日累计按上海执行日、同一用户所有付款账户的已成功转账汇总，包含本次。累计不超过 1000 元需要确认；超过需模拟强验证。
- 最终授权、累计复查、余额检查、双边记账、原结果保存、挑战消费及成功审计在同一 SQLite 写事务提交。待授权期间不长期占锁或占额度；多笔并发授权按实际提交顺序重新分级。
- 若待确认操作在执行时越过累计门槛，旧挑战失效并创建新的待验证挑战；不能再用旧确认完成。已经要求强验证的挑战不会因跨日降回普通确认。
- 同一挑战累计连续 5 次无效模拟验证后，持久化 `blocked / SAFETY_LOCKED`；前 4 次抛出 `ServiceError(AUTH_INVALID)`，业务仍待验证。调用方应重新查询原操作，不能将该异常当成整笔交易终态失败。重新签发凭证不清零次数，并使旧凭证失效。
- 错用户无法取凭证、授权或消耗别人的失败次数；对已知模拟用户记录拒绝审计。未知身份或数据库故障时可能无法写审计，但仍拒绝执行。审计不保存凭证明文或他人的请求内容。
- 锁定范围仅为本次操作；重新发起新键是新操作。这不是账户级反欺诈。凭证只能在可信演示环境使用，尚无真实登录或外部验证提供方。

## 异常处理与恢复边界

可证明局部事务已回滚时，网关保存终态失败及失败审计，不留下扣款、入账或成功审计。外层提交结果不确定时，返回/抛出 `RESULT_UNKNOWN`，不写一个“失败”去覆盖可能已经提交的成功。

确认失败前后的恢复仍使用原动作和幂等键查询。已有 `unknown/running` 记录不会再次执行。P3 测试已覆盖“挑战已保存但回执丢失”和“资金已提交但回执丢失”的后端查询；客户端自动恢复、刷新恢复和页面按钮行为属于 P4/P5，当前不能宣称完成。

## 存储升级

存储版本由 2 升到 3，为 challenges 增加收款账户绑定字段。`python -m bank.seed init` 保留余额、流水和操作，支持版本 1 经资金表升级到 3；不重置模拟银行。旧的待授权记录若没有账户绑定，不允许自动补绑并扣款，应重新发起确认。未知库身份/版本仍拒绝初始化。

## 本次选择与后续复核

选择沿用 SQLite 短写事务、10 分钟挑战、同挑战 5 次失败锁定、服务端随机模拟凭证。这样可以在没有成员资料、模型密钥或短信服务的条件下完成本地闭环，并复用现有接口。B 仍需复核规则，C 仍需独立手算和验收。
