## 1. 本轮修改

- 新增结构化计划资源边界：JSON容器深度最多16、节点最多4096；输出最多30000字符，历史最多32条且累计JSON最多24000字符，计划最多20步。原有请求64KiB、响应256KiB、45秒超时、无自动重试保持。超过边界即拒绝草稿，不截取半个JSON继续执行业务。
- 模型草稿连续5次异常后停止当前会话，回退、继续、暂停不能恢复旧草稿；核实后通过“新需求”重开。一次有效草稿重置连续失败计数。这是新增的模型技术熔断，不改变资金规则、日累计门槛或银行验证失败5次的持久锁定。
- 为模型请求、合法/拒绝草稿、暂停/继续/回退/接管/重开和实际步骤增加`agent.plan`审计。元数据采用闭集校验，不收提示原文、模型自由文案、密钥、验证码或验证令牌。审计不可用时停止新的模型推进；已提交交易保留实际结果，不改写成未扣款。
- 每个需求的`plan_…`跟踪号由可信代码生成，贯穿模型决策与实际银行动作；原共享v1.1、存储v13、银行业务动作与授权协议不变。普通表单仍使用原流程。

接线范围为[计划边界](../agent/model_safety.py)、[对话状态](../agent/model_dialogue.py)、[计划执行器](../agent/model_bank.py)、[可信银行流程](../agent/controller.py)、[审计](../bank/gateway.py)、[页面接线](../app/model_bank_panel.py)。本轮属于安全/权限变更及独立最终验收，由Codex直接处理，未发起DeepSeek编码委派。真实DeepSeek业务验收与编码委派是两件事。

## 2. 沙箱与信任边界

赛题原文为“生成的代码在受限、可监控的逻辑隔离环境中运行”，见[技术要求截图](../项目要求-非代码/屏幕截图%202026-10-10%20194644.png)。本系统只接收声明式JSON业务计划，不提供任意生成代码的解释器或文件/命令工具。采用下列逻辑边界：

1. 模型结果只作为不可信数据，先通过限长、限深、闭集字段、意图和DAG检查。
2. 可信编译器只映射已有动作；账户身份来自服务端，归属、收款人、金额和实际对象重新核验，不能从模型提供`principal_id`、`confirmed`、证明或风险分数。
3. 银行网关独立控制确认、模拟强验证、摘要/时效/归属、幂等、事务与账本；模型说“继续/已确认”不能代替这些入口。
4. 决策与银行操作可按同一跟踪号关联；失败熔断、审计失败阻断和unknown恢复分别验证。

实测脚本/SQL/内部credit/伪造授权输出、用户文字及商户名/订阅依据注入均未得到额外文件、命令或银行权限。脚本字符串即便位于允许的说明文字中也只保留数据意义，没有执行路径；相关临时标记文件未生成，账户未被越权修改。

**边界限制**：没有独立OS进程沙箱、容器、主机文件ACL隔离或防管理员篡改的外部审计服务。可信程序本身需要访问模拟库与显式授权的密钥来源；同一主机上能修改代码/数据库的用户不在模型输出隔离保证内。本报告证明的是上述受限、可监控的声明式计划执行边界，不证明任意生成代码可安全运行，不承诺所有攻击措辞或生产环境均安全。

## 3. 六场景的实际页面联测

使用真正的Streamlit页面与临时SQLite账本，模型响应在此组由测试明确模拟。核心用例：[六场景及中断恢复验收](../tests/test_closeout_acceptance.py)。没有把模拟模型响应计为真实模型调用。

| 场景 | 实际走通的流程 | 账本/状态断言 |
|---|---|---|
| 转账 | 输入→缺金额追问/补充→准备→确认或模拟强验证；拒绝、刷新与新页面恢复 | 20元只扣一次；1200元丢失回执后按原键恢复，余额80000分且只有1笔转账 |
| 生日 | 依赖计划→预留35700分→下单19900分→释放15800分 | 连续链承接转账后的198000分，最终178100分；预留归零、订单1笔；暂停/接管后不自动下单，未用预算可单独释放 |
| 账单 | 对话意图→实际账单查询→显示银行回执 | 上述消费19900分，鲜花分类19900分，转账不误算消费 |
| 理财 | 明确5题答案→实际评估回执→申购50000分→7天后赎回200份 | 申购499.5000份；部分赎回实际入账20000分，连续链余额148100分 |
| 卡片 | 挂失→解挂→单独解冻，分别走原授权 | lost→frozen→active；不更改账户余额 |
| 订阅 | 核实→本期单独强验证续费→取消 | 核实不扣款，续费2500分仅1笔；取消不退已发生消费，连续链最终145600分 |

另验证：五次无效模型草稿的页面锁定与手动重开；五次错误验证凭证后，重新打开页面仍恢复`SAFETY_LOCKED`，没有扣款。此处实际执行了服务端错误凭证，不把按钮文案当安全证据。

申购即时模拟确认；赎回即时展示入账以模拟T+1，并未启动真实跨日结算。调度/提醒仍需手动检查；生日不代表程序关闭后自动下单。人工接管只交还本页控制权，不对外发送消息。自动化页面验证不等于人工逐像素体验评审，最终录像和展示检查在F4完成。
