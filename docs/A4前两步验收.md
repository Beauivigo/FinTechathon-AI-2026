## 第一步固定标准

纯函数`route(text, draft=None)`只返回展示草稿：`status / intent / fields / missing / message`。输入限200字；字段来自明确输入，不把草稿当公开银行请求或授权。账户、资源ID、金额文字、日期缺失时追问，不补造。金额只保留原文，真实换算及业务校验仍由已有模块完成。

固定输入矩阵见[evidence/2026-10-19-routing-cases.json](evidence/2026-10-19-routing-cases.json)，35条；独立验收见[测试](../tests/test_routing_acceptance.py)。多意图不挑第一项执行；否定/取消草稿不取消已提交业务；取消订阅独立识别。多轮只合并明确补充字段，新意图不继承旧草稿。未知和未实现业务明确告知。

## 第二步固定标准

新增需求入口展示目标、已给字段、待补问题。点击进入对应表单才导航，导航不执行操作；实际业务使用原表单及原确认/强验证/恢复流程。原普通转账聊天保留。待确认或待核实时阻止新的业务入口，不能靠清除草稿绕过。

页面组件不接收网关、数据库或授权对象；识别/显示交DeepSeek，涉及确认和恢复的接线由独立复核处理。使用Streamlit AppTest验证输入、追问、清除、导航、刷新和待办阻断；临时库证明识别与导航不产生资金变化。必须完成原功能回归；未执行或跳过的测试不计通过。
