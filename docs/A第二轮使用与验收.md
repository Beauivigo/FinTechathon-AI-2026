# A 第二轮：单笔模拟转账的使用与验收

本交付完成《A 第二轮开工方案》的 P0—P6，也就是第二轮 2.1 单笔转账底座。账单、理财、卡片/订阅、完整模型路由和生日计划属于后续步骤，并未随这次完成。

## 启动

安装 Python 3.10+ 后，在项目根目录执行（已创建虚拟环境时不必重复创建）：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-app.txt
.\.venv\Scripts\python.exe -m streamlit run app/main.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

也可以运行 `启动A演示.ps1`。打开 http://127.0.0.1:8501 ，停止时按 Ctrl+C。无需模型密钥、短信服务或他人业务数据。

首次打开页面会初始化项目内 `runtime/sandbox.sqlite3`：A 的余额 2000 元，李明与两个小王各 0 元。之后打开、刷新或重启均保留模拟余额、流水、原操作与授权。数据完全虚构，`demo_otp` 仅演示，不代表真实银行或身份认证。页面仅绑定本机地址。

## 五分钟复现

以下从初始余额开始。已有记录时先处理全部待办，再按文末步骤重置演示库；不要用重置规避未知结果。

1. 输入“给小王转钱”，应追问金额；输入“200元”，应出现尾号 1234、5678 两个小王，不能自动选择。
2. 选一个小王，页面显示 200 元和对应尾号、待确认状态，余额仍是 2000 元。点击拒绝，不产生转账流水。
3. 输入“给李明转200元”，点击确认。A 可用余额变为 1800 元，新增一条转出流水，结果标明模拟。刷新不会再次扣款。
4. 输入“给李明转900元”。这时日累计含本次是 1100 元，页面要求模拟强验证；没有普通确认按钮。验证后 A 为 900 元，李明为 1100 元，共两笔成功业务。
5. 再输入“给李明转200元”，先不确认。刷新或重新打开页面，在“恢复待处理操作 / 查看历史”中恢复原操作，仍应等待用户确认；点击拒绝结束。
6. 在历史里恢复刚才已成功的操作，看到的是原结果，余额不变。新建对话只清聊天草稿，也不改变账本。

可运行 `python -m examples.gateway_demo` 验证同一 200+900 元算例。它每次使用独立临时库，不影响页面银行。其余故障用例由测试注入，不要求成员修改源码模拟。

## 页面状态的含义

| 状态 | 页面行为 | 资金事实 |
|---|---|---|
| 待确认 | 核对对象/金额后确认或拒绝 | 尚未扣款 |
| 待模拟验证 | 服务端模拟凭证完成后继续，或拒绝 | 尚未扣款 |
| 已完成 | 展示已保存的流水编号 | 已提交本地模拟账本 |
| 已拒绝/失败/锁定 | 展示原结果；不能继续旧操作 | 本次未成功执行 |
| 待核实/执行中 | 保留原操作编号，点击“查询原操作结果” | 不能猜测是否已完成；禁用新提交、新对话和重置 |

查到原操作时，按原操作内层状态展示；“查到记录”不会被显示成“转账成功”。查不到记录也不能证明未扣款。未决操作会保留在恢复列表中，已结束操作展示最近 20 条；流水区展示近 30 天记录。

## 重置与故障

正常新建聊天不重置数据。需要重演初始数据时，先处理全部待办，在侧栏展开“重置本地模拟银行”，勾选清除模拟数据，再点击确认重置。该操作会清除模拟交易、授权、审计和流水，恢复种子余额。待处理/未知结果时不开放页面重置。

管理员命令仅作用于本项目固定演示库：

```powershell
.\.venv\Scripts\python.exe -m bank.seed init
.\.venv\Scripts\python.exe -m bank.seed show
# 明确需要清除模拟业务时才执行下一条
.\.venv\Scripts\python.exe -m bank.seed reset --confirm-reset
```

初始化不会重置数据；已知存储版本会保留数据升级。未知版本或损坏数据库会拒绝打开，不能通过页面自动删除重建。真实运行库及凭证不上传 GitHub。
