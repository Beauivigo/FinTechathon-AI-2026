## 配置与使用

按根[README](../README.md#启动页面)启动，从首页左侧进入“AI对话办理与模型设置”。旧“用一句话准备其他业务”展开区也有真实模型入口，下面的离线备用不会伪装成模型调用。

在AI助手左侧展开“模型设置”：

1. 选择服务商和模型，输入对应API密钥，点击“保存或修改独立密钥”。已保存密钥不会回显，成功后清空输入框；修改仅影响后续新请求。
2. 本机装有桌宠且需沿用时，点击“沿用桌宠本机配置”。本次已获用户明确授权并完成真实调用；不修改桌宠的密钥、聊天记录或设置。
3. 点击“清除独立密钥并停用本机配置”可删除银行项目保存的独立密钥并停用该本机来源。部署环境变量若仍存在，会继续优先使用，页面已提示这一点。

银行独立密钥使用Windows当前用户DPAPI加密，保存于已被Git忽略的`.cache/bank-model/profile.json`；没有明文落盘降级路径。该文件绑定当前Windows用户，不应作为可迁移密钥包分享。非Windows部署可使用环境变量。本轮只在Windows实际验收。

| 配置 | 含义与优先级 |
|---|---|
| `BANK_MODEL_API_KEY` | 银行项目显式密钥，优先于本机保存配置 |
| `DEEPSEEK_API_KEY` | 仅官方DeepSeek地址下的备用环境变量；不会自动发送到本地端点 |
| `BANK_MODEL_PROVIDER` | 选择服务商；编号和对应密钥配置见顶部多服务商说明 |
| `BANK_MODEL_NAME` | 显式模型名；默认按同服务商本机独立配置或该服务商首个预设选择 |
| `BANK_MODEL_BASE_URL` | 默认按服务商选择；也接受字面回环地址的HTTP兼容端点，禁止任意外部地址和重定向 |
| `BANK_MODEL_USE_DESKTOP_PET=1` | 显式启用本机桌宠凭证来源；也可通过设置页面选择 |

传输配置函数也可接受服务器传入的配置映射；当前页面默认读取环境与本机配置。本地模型只具备兼容协议入口，尚未安装或实测任何本地模型，不能据此宣称本地模型已交付。

可先输入“我的账户还有多少钱”，或“给小王转钱”后补金额；同名收款人由银行端候选列表消歧。涉及付款时先核对账户、收款人和金额，再按原确认/模拟强验证办理。不要在对话中填写API密钥、密码或验证码；密钥使用设置框，模拟验证使用银行原验证控件。

## 实现与信任边界

复用桌宠现有DeepSeek消息/JSON协议、模型名兼容、超时及错误处理方式。银行使用独立业务提示和受控执行器，未复用桌宠人格或情绪逻辑。桌宠已保存密钥通过现有Electron安全存储只读解密，在私有子进程管道与当前请求内存中传递；不打印或另存明文。桌宠路径为`D:/Desktop Pet/gpt project`，离开此电脑时建议配置银行独立密钥。

| 文件 | 职责 |
|---|---|
| [model_client.py](../agent/model_client.py) | 标准库HTTP调用、完整JSON校验、限长、超时、禁止重定向及脱敏错误；不自动重试付费请求 |
| [model_credentials.py](../agent/model_credentials.py)、[桌宠桥接](../scripts/desktop_pet_model_key.cjs) | 独立密钥加密保存与桌宠凭证只读复用；模型不接触密钥 |
| [model_dialogue.py](../agent/model_dialogue.py) | 银行业务结构化意图、追问、改参、任务依赖及会话控制；不持有网关或授权证明 |
| [model_runtime.py](../agent/model_runtime.py) | 从本地银行读取所属账户、产品等上下文，补充已有真实回执；每次新请求读取当前模型设置 |
| [model_bank.py](../agent/model_bank.py) | 白名单动作编译、参数校验、真实收款人消歧、依赖执行与银行回执绑定 |
| [model_view.py](../app/model_view.py)、[model_bank_panel.py](../app/model_bank_panel.py) | 展示草稿和任务、核对后准备写操作、沿用原确认/验证/恢复控件 |

模型只能提出候选动作和字段，不能决定风险等级、提供验证凭证、替银行声明执行成功。模型输出带有伪造状态、未知字段、越权参数或无效依赖时拒绝编译；账户归属、收款人、金额、状态及业务规则由银行端复核。自由模型文案不作为银行事实展示，业务结果只展示网关实际回执。

支持余额/账单、转账/定时/AA、卡片、订阅、理财/产品、生日/预算/商户等已存在业务动作。问卷缺答案时仍进入真实问卷，不能凭模型补答。任务最多20项，无循环或缺失依赖；预留号等跨步骤参数只能引用成功祖先任务的实际回执。

纯查询可自动执行；写操作需用户核对并准备，再进入原黄色确认或红色模拟强验证。刷新不重复调用模型或另建付款，未知结果先恢复原操作，待办结果不明确时不继续后续任务。暂停、人工接管和返回草稿只停止后续或撤回未提交内容，不回滚已入账交易。人工接管只在当前页面交还控制权，不对外发送消息。

本轮未改变共享v1.1契约、存储v13或既定资金规则，未接入真实银行、真实身份认证或后台自动扣款。生日任务不等于程序关闭后仍能自动下单，模拟订单不代表真实配送。不执行模型生成的代码，也不承诺任意领域闲聊或任意措辞均正确识别。

协议依据：[DeepSeek JSON输出](https://api-docs.deepseek.com/guides/json_mode/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[对话接口](https://api-docs.deepseek.com/api/create-chat-completion/)、[模型列表](https://api-docs.deepseek.com/api/list-models/)。本轮结构化识别使用非思考、非流式JSON响应。

## 后台数据检查与安全边界

目前数据来自`runtime/sandbox.sqlite3`本地模拟账本，不是实时银行接口。后台在查询、发起、授权及入账等节点检查数据，不是一个持续运行的安全监控中心。AI负责理解和提出草稿，余额、统计与执行结果由程序和账本给出。

| 检查位置 | 当前实际行为 | 依据 |
|---|---|---|
| 输入与响应 | 固定动作、字段和类型；金额使用整数分并校验范围；拒绝未知字段及非法状态转换 | [共享契约](../shared/contracts.py) |
| 账户与资源 | 查询和写操作按服务端提供的身份检查账户、卡、收款人及其他资源归属 | [业务服务](../bank/services.py)、[执行网关](../bank/gateway.py) |
| 资金与一致性 | 余额=可用+预留；数据库外键和唯一约束；写事务及保存点失败回滚；业务条件在授权时重验 | [存储](../bank/store.py)、[执行网关](../bank/gateway.py) |
| 授权与防重放 | 绿/黄/红分级；黄确认、红模拟强验证；10分钟有效期，连续5次错误锁定本次操作；绑定原用户、动作、参数和操作键 | [权限计算](../shared/policy.py)、[执行网关](../bank/gateway.py) |
| 重复和不确定结果 | 同键同内容重放原结果，同键改参拒绝；结果未知先核实原操作，不盲目新建付款 | [执行网关](../bank/gateway.py)、[模型任务执行](../agent/model_bank.py) |
| 审计与回归 | 保存操作、授权及执行事件；异常、越权、并发、回滚、恢复等由隔离模拟库测试验证 | [执行网关](../bank/gateway.py)、[提交前全量](evidence/2026-10-21-publish-full.json) |

账单统计按日期与既定类别计算消费/订阅毛支出和退款；不让AI编造分类或金额。当前异常提示只启用C1-003-R03分支A：消费、订阅、转账或理财的借方单笔金额≥5000元。借贷配对、跨期退款、理财收益率等未定/未启用规则不会自动判为异常；没有提示也不代表没有风险，见[账单计算](../billing/__init__.py)。

模型可见内容包括用户对话、当前身份范围内的账户标识、卡片状态/限额、产品、持仓、模拟商品/地址，以及已执行步骤的业务回执。这些请求内容会通过HTTPS发送到所选模型服务商的官方接口；本地保存数据库不等于数据完全不出本机。当前验收只用虚构数据。未来接真实个人数据前，应另行完成逐字段最小化、脱敏、授权和服务方数据处理范围审核，不能直接沿用当前演示上下文。

密钥不放进模型提示词，独立密钥按当前Windows用户加密、密码框不回显、日志不输出明文，日常库与密钥文件不提交Git。DPAPI不防已控制当前Windows账号的程序；普通SQLite账本未做文件加密，审计表也不是不可篡改存储。数据库约束可挡非法写入，不能阻止有本机文件权限的人整库替换。

页面当前使用固定演示身份和模拟验证，不具备真实多用户登录、密钥设置管理员权限、完整服务级限流、主动安全告警或独立渗透测试结论。默认启动绑定127.0.0.1；若要公网或接真实账户，必须先实现相应身份与权限隔离、生产验证、访问保护、日志告警和备份恢复，再独立验收。当前不能宣称银行生产级安全。服务端交易授权和模型权限隔离的设计原则可对照[OWASP交易授权](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html)及[模型注入防护](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)；本项目未获得OWASP认证。
