## 1. 定时转账备注（本轮用户明确授权扩展共享契约）

- `shared/contracts.py`：`transfer.schedule` 增加可选 `memo: string`，与 `transfer.create` 同义：非空字符串、契约层最多 4096 字符；模型层沿用 1—200 字符限制。版本仍为 v1.1 的可选字段，其他共享字段、版本语义和模块边界未变；`shared/policy.py` 未改。
- `agent/model_bank.compile_task`：单笔与定时转账共用同一备注校验（去首尾空白、拒绝空/全空白、超过 200 字符拒绝、身份/授权/验证字段仍拒绝），定时不再拒绝备注。
- `bank/scheduler.spec_for`：登记时把可选 `memo` 写入到期固定的 `transfer.create` 执行 payload；旧登记请求没有 `memo` 时，重新计算的 spec 与原任务完全一致，旧已登记任务继续可执行。
- 完整链路：模型澄清/修改 → 可信编译 → `transfer.schedule` 登记（操作记录含备注）→ 计划持久化/重启恢复 → 到期由调度器生成 `transfer.create` 待确认/待强验证操作（固定执行键，含备注）→ 原银行确认/TOTP（本工具与测试用演示确认/测试 TOTP）→ 原操作查询/恢复保留备注。`operation.get` 返回的原请求是权威数据；账本本身不新增备注列，符合既有“备注不进入账本”约定。
- 安全边界不变：备注只是业务文本，不参与指令、身份、风险或授权判断；相同登记幂等键改备注会 `IDEMPOTENCY_CONFLICT`，不会静默覆盖；未知结果必须查原操作，执行重试复用固定执行键，不重复扣款。
- 兼容性：旧无备注的 `transfer.schedule` 请求、旧操作记录和旧已登记任务均保持原 payload；新增字段为纯可选、向后兼容，不需要迁移数据库或 schema_version。

## 2. 当前版验收工具 `scripts/evaluate_closeout_model.py`

旧工具固定 2026-10-23、生日用例不经过完整生日草稿编译，不能验收当前实现；本文件已整体更新。默认**离线**，只有显式 `--live` 才可能联网。

### 2.1 离线自检（默认，本环境已实际通过）

```text
python -B -X utf8 scripts/evaluate_closeout_model.py
```

- 使用真实临时 SQLite 模拟银行 + 脚本化模型回复；不联网、不读授权账本、不写 `docs/evidence`、不触碰日常 `runtime/sandbox.sqlite3`。
- 与真实页面相同的可信转换：单任务/计划 → `BankPlanRunner` + journal + `checkpoint`；生日完整草稿走 `schedule_ready`/`tasks_from_slots`；修订走 `inherit_completed` + `checkpoint`，并验证丢失时间约束的修订被拒绝且原计划不变。
- 覆盖 11 组：六场景（转账/账单/理财/卡片/订阅/生日）、单笔备注、定时备注、生日完整时间链、修订约束、注入、问卷澄清、旧无备注定时任务兼容。
- 输出 PASS/FAIL；退出码 0 表示全部通过。离线记录明确 `simulated_model=true`、`network_model_requests=0`，不得拿来冒充真实模型结果。

### 2.2 在线真实 DeepSeek（留 Codex 执行；本任务未联网）

```text

python -B -X utf8 -c "import json,pathlib; p=pathlib.Path('.cache/2026-10-26-closeout-model-budget.json'); p.parent.mkdir(parents=True,exist_ok=True); p.open('x',encoding='utf-8').write(json.dumps({'limit':20,'used':0,'provider':'deepseek'}))"

python -B -X utf8 scripts/evaluate_closeout_model.py --live --suffix f1
```

- 账本固定为 `.cache/2026-10-26-closeout-model-budget.json`，`limit` 只接受 1—20，工具内部再用 20 封顶；`used` 只增不减，工具没有重置入口；缺少账本时拒绝执行并给出一次性创建命令。
- 只允许 DeepSeek：解析出的 provider 不是 `deepseek`、或凭证来源为 missing/local 时，在发送请求前拒绝，不自动切换服务商。第二轮配置的其他服务商**本轮未测试**，不能写成五家均通过。
- 每次模型请求前先在账本中+1，失败也保留已用次数；没有自动重试，模型错误直接记为该组失败。证据逐组落盘：证据路径为 `docs/evidence/2026-10-26-closeout-<suffix>.json`，已存在则拒绝，不覆盖 2026-10-23 等旧证据。
- 证据字段：`mode/provider_under_test/providers_tested/providers_not_tested/request_limit/planned_cases/six_scenarios/cases/model_calls/ledger_before/ledger_after/source_sha256/tool_sha256/runtime_unchanged/bank_scope/auth_scope/phone_scope/passed`。`model_calls` 记录实际请求序号、模型、来源、token usage（仅服务端返回的 prompt/completion/total tokens）；不推算费用，失败保留 error 类型与简短消息。
- 模型调用与银行模拟、测试 TOTP、本人手机验收分离：工具内的红色操作使用本地演示确认/模拟验证；工具不输入真实 TOTP、不登录手机、不代替本人扫码。真实页面/AppTest 与真实后台进程仍由 Codex 最终环境执行。
- 源码哈希使用文件系统扫描（排除 runtime/.cache/等），不依赖 Git 元数据，离线与在线都可生成。
