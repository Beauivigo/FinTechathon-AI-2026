# 现有资料下的开发方案：C 资料只读校验与导入前检查

编制日期：2026-10-14。状态：**方案已制定，V0—V5 尚未执行**。A 负责全部编码，B/C/D/E 负责各自业务资料与独立复核。V 是本批开发步骤编号，与成员编号、前批 B0—B4 无关。

依据：[开发规则](开发与需求阻塞处理规则.md)、[最新资料和阻塞清单](BLOCKERS.md)、[账单基础验收记录](账单基础验收记录.md)。所有待补问题、负责人答复与解除依据只维护在 BLOCKERS；本文规定如何继续工作，不复制一套待补清单。

## 1. 当前基础与本批目标

目前已完成单笔转账底座，以及 B0—B4 账单基础统计、网关和页面的本地技术验收：198 项测试，其中 19 项页面测试，0 跳过。账单支持按账户和上海日期统计消费/订阅毛支出，退款另列。未完成的其他业务不能因这一结果标为完成。

现有材料为仓库外的 `D:/FinTechathon-AI-2026/群组资料/副本账单数据与手算（C项目）V1.1.xlsx`。上次最终复核版本有 10 张表、15 条流水，SHA-256 为 `f41c74ec6b7121770352d8b966bc634b3dbe3bc8958830d06704fd9eebbb0127`。这是历史核对点；V0 开始时重新读取指纹，不能假定同名文件内容未变。

本批交付一个可重复运行的资料检查工具：给定 Excel，输出带工作表、行号/单元格、原因、影响和 BLOCKERS 引用的问题报告，并独立复算资料中的月度及分类金额。成员修改 Excel 后可重新检查，看哪些问题已经修正。

**本批完成的含义是“工具已实现并通过测试”，不是“这份材料已全部合格”或“可以写入银行账本”。** 当前资料仍有待决议内容，正确的报告应当如实指出它们。

## 3. 实施顺序和每步验收

每步只在本步验收通过后进入下一步。技术实现失败就修复本步；业务材料缺失则记录并跳过依赖该材料的检查，不中断其余检查，也不把跳过算通过。

| 步骤 | 具体工作 | 交付物 | 本步通过标准 |
|---|---|---|---|
| V0：固定基线与输入 | 核对 main、已通过代码和测试；记录原文件指纹、版本、读取时间及已有阻塞；列出现有表头 | 本批基线记录、检查项与输入清单 | 能确定本次检查的是哪个文件内容；原表与运行库不变；已完成业务基线可复现 |
| V1：只读解析 | 将同一份文件字节读入内存；分别读取公式与缓存；定位工作表/表头/数据行；保留每个值的来源和原始精度 | Excel 读取模块和针对性测试 | 15 条原始流水不遗漏；不把尾部说明当流水；列移动能按名称解析；缺表、重名表头、坏文件有明确诊断 |
| V2：字段与引用校验 | 检查必填、唯一 ID、日期、金额、方向、类型/分类；检查引用存在性与未确认状态；记录公式错误和可定位的已知矛盾 | 带单元格定位的检查结果 | 能区分确定错误与待人工决议；不自动改“小李/小王甲”、不替换账号、不补余额和时刻 |
| V3：独立金额复算与差异 | 从原始流水独立计算月/分类毛支出与退款；核对统计缓存、手算、测试范围；生成安全字段的转换预览 | 复算表、差异列表、转换预览 | 当前版本总毛支出 347050 分、退款 34400 分；正确区分现金流与毛支出；原表自身有错时不会展示“全部通过” |
| V4：报告与重复检查入口 | 加 CLI，输出 Markdown 与 JSON；标明版本、计数、定位、影响；按稳定问题编号对比两份已生成报告 | 一条检查命令、成员可读报告、问题变化摘要 | C 能根据单元格定位修正；新报告明确绑定新文件指纹；未重检/失败不能复用上一份成功结论 |
| V5：整体验收与交接 | 跑资料工具专项、现有全量/页面测试和必要演示；验证无写入；更新使用说明及证据 | 验收记录、复现命令、成员操作步骤 | 原表/桌宠/日常库未改；既有业务不回归；当前材料缺项仍报告；明确工具完成与资料就绪两个结论 |

V0—V5 都可在不等待 B/D/E 新材料的情况下开发。V3 的正式账户导出仍受限制，但不会阻止整体/分类复算和诊断报告交付。

## 4. 各阶段的关键实现约束

### V0：固定检查对象

读文件时先一次性获取内容并计算 SHA-256，后续公式视图、缓存视图及检查均从同一份字节创建，避免检查期间别人保存 Excel 造成数据前后不一致。结束时可再次比较磁盘指纹：若变化，报告“源文件已更新，本报告对应旧指纹，请重新运行”，不把新旧两版结果混在一起。

原始 Excel 保留在用户指定位置。本批无需把整份原表上传仓库；仓库提交代码、合成的小样例、文档与必要验收证据。新增的本地检查输出放在单独忽略目录，例如 `local_reports/material_checks/`，不得写入银行 `runtime/`。

### V1：读值与公式分开

优先以一个离线 Excel 读取库处理 xlsx，并使用标准库 Decimal/日期/JSON 完成校验与复算；实现时检查运行环境，再决定是否增加单独的资料检查依赖文件。当前业务页面不因本批增加 Excel 依赖。

不使用 Excel 自动执行宏，不计算或执行任意单元格表达式，不通过 eval 执行手算文本，不访问外部链接。读取保存的公式结果必须标为“缓存”，不能声称运行过 Excel 重算。

按表名和表头确定字段，列顺序变化不影响读取。流水范围根据有效行识别，不写死第 3—17 行；空白、标题、脚注与半条数据要分开处理。缺失必要表/列、损坏或加密文件、重复表头应给明确错误；可读的无关表不应使所有检查停止。

月份从原始日期重新计算，检查月份公式缓存是否一致。日期只有年月日时保留 `source_date` 和“日期精度”，不立即输出 `occurred_at`。将来若批准用午夜占位，仍须保留其归属占位属性，不能称真实交易时刻。

### V2：金额、字段和关联

| 检查对象 | 可以直接判断的内容 | 不能自动推断的内容 |
|---|---|---|
| 流水编号 | 空值、重复、非法格式；保留行位置 | 不能为缺失记录生成业务流水 ID |
| 金额 | 数字有限、精确到分、方向符号一致、范围符合安全整数 | 不把空值当 0，不对多余小数静默四舍五入，不猜单位 |
| 类型和分类 | 六类映射来自字典；消费/订阅分类非空；未知值报错 | 不根据商户或摘要发明分类；非消费的“—”不猜成正式分类 |
| 日期 | 是否合法日期、月份是否匹配、已提供的时区是否明确 | 不造时分秒，不把无时区时间默认为真实上海时刻 |
| 账户与渠道 | 源编号唯一、引用存在、绑定指向有效账户、循环/冲突/缺失 | 不自动批准 C 草稿与 demo 账户映射，不生成用户身份 |
| 收款人与关联 | 引用是否存在，显式矛盾是否需要确认 | 不做任意中文语义“自动纠错”，不将不同尾号认作同一人 |
| 公式 | 缓存缺失、Excel 错误值、依赖月份与原日期不符 | 不把有缓存视为公式必然正确，不替用户重写原表 |

确定可转换的金额使用 `Decimal(str(原值))` 等精确路径验证，只有分位为整数才形成正整数分与 credit/debit 候选。布尔值、NaN、无穷、超过范围以及不符合契约的零金额不得伪装成有效流水。

V1.1 的“字段说明 H5 为 #NAME?”可自动定位；“小李/小王甲”等跨文本矛盾可以作为本版本已登记的人工复核项引用，不承诺一个通用模型能可靠判断所有中文关系。若采用版本特定断言，必须绑定输入指纹；资料变化后显示待复核，不凭旧行号宣布问题仍存在或已修复。

### V3：复算和预览不得变成隐式导入

复算继续使用已确定规则：消费/订阅出账计入毛支出；收入、转账、理财排除；退款入账另列，年费计入扣费期间。用原始日期和原始金额独立累加，不从“统计结果”抄答案再与自己比较。

当前版本应得到：

| 原表整体期间 | 毛支出（分） | 退款（分） | 说明 |
|---|---:|---:|---|
| 2026-08 | 48990 | 29900 | 属于资料整体复核，非单账户接口响应 |
| 2026-09 | 298060 | 4500 | 同上 |
| 合计 | 347050 | 34400 | 分类合计应等于毛支出 |

分类预期来自逐笔复算：8 月日用百货 32850、餐饮 8640、交通 5000、影音会员 2500 分；9 月住房 250000、日用百货 41260、云服务 6800 分。金额正确不自动证明账户归属正确。

原表手算负值可报告“与非负毛支出口径的符号不一致，绝对值一致”，不能静默改成正值后宣布原表通过。对于无效金额或缺失关键字段，不输出貌似完整的合计；可列出已检查有效行的小计，但必须显式标为“不完整，不可作为验收答案”。

转换预览只包含原始行位置、源编号、源账户/渠道、已确认的类型/分类和可验证的金额候选；未确认账户、时间、关联保留未解析状态。它是内部资料工具结果，不是 transaction、BankGateway 请求或新的共享接口版本。

本批默认不生成可供正式导入的 transaction JSON，不写 ledger_entries、不创建 principal/账户、不调用 post_funds。账户确认后另开资料适配/隔离试导入阶段，不能从“部分预览成功”跳到运行库写入。

### V4：报告格式与成员使用

报告先说明检查对象和结论，再列问题。每条问题至少包含：检查编号、等级（错误/待确认/提示）、工作表与单元格、观察到的事实、对应规则、影响范围、适用的 BLOCKERS 编号。此等级仅用于离线报告，不添加到共享业务状态。

JSON 与 Markdown 必须由同一份结果生成；金额采用整数分，来源位置和未完成项可追溯。报告中区分“完成的检查、失败的检查、因材料不足未执行的检查”，不得用一个通过率掩盖未执行项。

CLI 预期形式如下，**命令目前只是规划，尚未实现**：

```powershell
python -m material_check --input "D:\FinTechathon-AI-2026\群组资料\副本账单数据与手算（C项目）V1.1.xlsx" --output-dir "local_reports\material_checks\本次检查"
```

输出新目录中的 `report.md`、`report.json`；同名旧结果默认不覆盖，使用新目录再跑。不修改、重算或保存原 Excel。命令退出码必须区分“工具无法完成”“完成但有错误/未决”“全部已执行检查通过”，具体值在实现时写进使用说明。非零退出码并不等于工具自身损坏。

比较报告时按检查编号和源业务编号关联；不依靠行号作为唯一键，因为插入行会改变位置。只对两次都实际执行的检查判断新增/持续/消失；缺表导致没执行不能写成“问题已修复”。不自动根据报告清空 BLOCKERS 的业务决议。

## 5. 建议代码位置与测试范围

以下是待新增的建议位置，开工时可合并相近职责，不预建空壳框架：

| 位置 | 职责 |
|---|---|
| `material_check/reader.py` | 只读 xlsx、字段定位、输入指纹、公式/缓存读取 |
| `material_check/checks.py` | 字段/引用校验、确定口径复算、差异 |
| `material_check/__main__.py` | 参数、报告输出、退出码和两次检查对比入口 |
| `tests/test_material_check.py` | 小型合成工作簿及输入/报告边界测试 |
| `docs/资料校验使用与验收.md` | 实际启动命令、证据、工具与材料状态 |

不为本批新增 Web 服务、数据库、模型调用或第二套账单业务接口。与 `billing/` 共享已有契约和金额上限；整体原表复核保持离线属性，不能为了调用 bill.analyze 造一个汇总 account_id。

测试至少覆盖以下有实际风险的路径，不预先承诺测试总数：

1. 有效样例、空表、列重排、增行、表尾说明、缺表/缺列、重复表头。
2. 重复/缺失 ID、符号与方向不符、超过两位小数、零/布尔/超范围金额、非法日期。
3. 月份缓存与日期不同、公式错误、无缓存；不得执行外部链接或任意表达式。
4. 未知账户、渠道绑定冲突、待批准映射、缺关联；问题必须定位且不会导出为正式流水。
5. 当前确定口径、现金流与毛支出分离、退款/年费、全账户复核与单账户预期分离。
6. 原文件检查期间变化、重跑、报告差异、输出目录已存在、读取/写报告失败。
7. 同一输入产生稳定的业务检查结论；原表字节/日常库不变；既有测试和页面不能跳过。

全量测试只在 V0 基线、本批集成或有回归风险时运行，局部步骤用对应专项验证；失败或代码改变后重跑受影响范围，不为增加次数重复跑已通过检查。
