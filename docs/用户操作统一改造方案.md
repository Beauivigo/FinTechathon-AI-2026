# 用户操作统一改造方案

更新日期：2026-10-28。状态：方案，尚未实施。

## 目标与依据

让第一次使用项目的人凭日常银行操作经验，就能判断自己在哪里、下一步做什么、是否会改变资金，以及业务是否已经完成。

本方案覆盖[新用户操作体验审查](2026-10-27新用户操作体验审查.md)的 UX-01—12 和订阅查询说明。当前核对基线为 main 的 `b5b5733ffe0ee1ef8b39133bf9d1c89054dea0d5`；本轮只形成方案，不改应用源码、不调用付费模型、不提交、不推送。

借鉴银行中熟悉的账户选择、信息填写、核对、验证和结果查询方式。建行公开指南展示填写后进入核对页，再确认办理；工行说明强调常用收款人、户名和账号核对及汇款明细查询。[建行手机转账说明](https://ebank.ccb.com/cn/ebank/20110330_1301468051.html)、[工行汇款说明](https://www.icbc.com.cn/page/721852540139634730.html)。这些是公开流程参考，不据此复制各银行的收费、时限、限额或认证规则。

统一办理主线：**填写信息 → 核对信息 → 确认/身份验证（按现有业务要求）→ 结果**。

查询使用适当的短流程，不强行为所有业务增加四个页面。金额、日期、权限、手续费和到账规则继续由现有业务服务决定，界面如实呈现。

## 一、统一操作约定

| 项目 | 统一约定 |
| --- | --- |
| 当前位置 | 页面名称与导航一致；同一功能无论从首页、侧栏还是 AI 进入，都进入同一业务和同一套结果展示。 |
| 主按钮 | 当前步骤一个明确的主动作。“下一步/核对信息”表示进入核对；最终按钮写“确认转账200.01元”“确认预留300.00元”等具体动作。 |
| 金额 | 输入、摘要、结果、图表均用元，两位小数；份额明确用份。内部保持整数分，使用现有金额转换与校验，不用浮点数直接计算资金。 |
| 对象 | 显示可信资源提供的名称、银行、已有账户尾号。没有尾号就不编造；内部编号放详情。不能核实对象时禁止确认。 |
| 默认值 | 金额、收款人、问卷答案不替用户作决定；付款表单默认空白待选。只有唯一可用付款账户可默认选中；示例语句放示例区。 |
| 时间 | 统一显示北京时间、完整年月日和时刻；在保存前展示登记时间与实际需处理时间的区别，不根据浏览器时区悄悄换算。 |
| 修改 | 未受理草稿可以修改；已经形成待确认原操作时，先按原机制结束旧待办，核实结束后再形成新草稿/请求；旧授权失效，已改内容重新核对。 |
| 取消 | “取消本次操作”“取消预约”“释放未用预算”分别说明影响，不能统称取消。已付款、已派发、结果未知按各自原规则处理，不能冒充撤销或退款。 |
| 提交反馈 | 显示处理中并防重复点击；后端仍使用原操作身份防重复。输入验证码本身不自动提交付款。 |
| 异常 | 错误紧邻字段；按钮不可用时解释原因和下一步。结果未知只提供核实原操作等合法动作，不提示换一笔重试。 |
| 文案 | 使用普通中文，减少内部版本、字段名和工程术语；代码、接口示例和技术状态保留在详情/开发者区域。 |
| 能力边界 | 入口与帮助保留一句项目性质说明，不在每个组件重复。不同功能的必要限制在决定前准确说明，不能把所有提示都删掉。 |

旧请求、已有操作记录、原操作编号和已保存计划继续兼容；不为统一页面改写历史资金事实。

## 二、用户看到的导航

使用同一套导航定义，保留现有功能与旧入口的兼容跳转。继续用当前 Streamlit 技术栈和现有视觉风格，不另换前端框架。

| 主入口 | 主要内容 |
| --- | --- |
| 首页 | 当前身份、账户与可用余额、预留金额、常用业务、待处理事项、近期交易、全部服务。 |
| 转账与收款 | 直接转账、预约转账、AA收款单；从现有可信收款人中选择或查询。 |
| 收支明细 | 当前账户交易明细与收支分析；时间筛选、原交易详情与可追溯回执。 |
| 理财 | 产品浏览与对比、风险评估、申购、持仓与赎回；选择的产品在相关步骤保持一致。 |
| 我的 | 本机登录、安全验证、银行卡、站内通知与后台运行设置、帮助；高级模型设置和开发者工具按需展开。 |

AI 助手在首页与全局导航保持显眼入口。首页“全部服务”明确列出订阅管理、预算管理、生日计划等生活服务，相关旧入口继续可达。

“资料账单”改为明确的“历史样例分析”，放在示例/帮助区域，显示独立资料账户与统计期间，不与当前登录账本合并。

取消所有业务页固定排列的无关快捷按钮。页面提供“返回上级”或“返回本次任务”等与当前任务有关的动作；没有合理上级时明确返回首页。

## 三、首次使用、登录与退出

尚未创建本机账号时，主区展示两个明确入口：

1. **体验示例账户**：说明正在使用现有示例账本；体验中持续显示简短身份标识。
2. **设置本机账号**：进入“设置用户名和密码 → 保存恢复码 → 绑定手机验证器”的主区向导。

向导说明：当前本机账号用于管理本项目现有账本，不是开立真实银行账户；完成设置不新增余额、不清空旧流水、不另建一套资金事实。

已有账号必须登录；设置未完成必须续接原设置。不得通过新的体验按钮绕过已初始化身份或未完成的绑定。已登录时显示可信会话的用户名与验证状态，不把固定“用户A”当成当前身份。

恢复码、密码、二维码和动态码只出现在专用界面，不进入 AI 聊天。手机验证器绑定继续沿用现有机制，不添加短信、刷脸或虚构实名认证。

“退出登录”结束当前会话；“退出应用”说明对本机后台运行的影响。关闭网页与停止后台的区别在退出/预约等相关位置说明，避免用户误以为关闭标签页就取消了计划。

## 四、各项业务的最终流程

| 业务 | 用户操作流程 | 成功或保存后应看到什么 |
| --- | --- | --- |
| 直接转账 | 选择付款账户和现有收款人 → 输入元金额及可选备注 → 核对服务端摘要 → 按原规则确认或输入手机动态码 → 提交 | 明确转账结果、对象、金额、时间、操作/交易详情入口；可查看明细或返回首页。 |
| AI 助手 | 描述目标 → 针对缺失字段补充/选择对象 → 展示可核对草稿 → 进入同一业务确认和验证组件 | 使用同一账本回执和状态；AI解释不能代替业务执行结果。多步任务显示每步实际进度。 |
| 交易明细/分析 | 选择账户和期间 → 查询 → 查看记录/统计 → 打开详情 | 当前账户及时间范围清楚，收入、支出、退款按既定口径区分，表格和图表同用元。 |
| 卡片 | 选择名称和状态清楚的卡片 → 选择冻结/解冻/挂失/解挂/设置限额 → 核对影响 → 验证 | 最新状态及生效范围；说明卡限额与普通账户转账的实际关系。解挂不冒充解冻，申请受理不冒充发卡。 |
| AA收款单 | 选择收款账户和参与人 → 输入总额 → 核对每人的元金额 → 确认创建 | “收款单已创建”，列出分摊金额；清楚说明未发送外部通知、未替参与人付款，不能显示已收款。 |
| 订阅 | 选择账户 → 明确授权读取本次订阅 → 查看已知订阅与待核实候选 → 选择核实/排除/取消/提醒/本期续费 | 每项动作分别说明结果。核实不等于签代扣，排除不等于取消；本期续费继续独立强验证。 |
| 预约转账 | 选择对象、金额、备注、时间 → 核对“到期后需本人处理”等条件 → 按原规则登记 → 查看预约 | “预约已保存”，同时显示后台是否运行、何时需要本人确认、失效条件和付款实际状态。 |
| 预算 | 填写用途和元金额 → 核对 → 确认预留；释放时核对实际可释放金额再确认 | 可用余额与预留分别显示。预留未付款、释放非退款；未知订单占用金额仍保留。 |
| 生日计划 | 日期/商品/地址 → 总预算与时间安排 → 一张计划摘要 → 保存 → 同页查看进度和待办 | 区分已保存计划、已授权预留、已下单、未开始及结果待核实；直接进入该计划，无须手工去AI页找编号。 |
| 理财 | 浏览/对比产品 → 选择产品 → 需要时完成未预填答案的风险问卷 → 核对费用、锁定与现有赎回条件 → 验证申购 | 实际回执和持仓；赎回按份额办理并展示原规则，不虚构收益或真实到账时效。 |

转账表单与自然语言入口共享同一草稿的业务含义，避免用户在两边重复填写或重复发起。首版只使用现有支持的收款人能力，不添加没有后端验证的新收款人/任意卡号付款入口。

已发生的业务记录以服务端恢复；页面重新打开不要求用户重建已保存计划或重新做已完成操作。未提交的输入回退时尽量保留，跨重启的未保存草稿不假装已经持久化。

## 五、状态、按钮和结果用语

| 实际状态 | 用户文案 | 允许的主要操作 |
| --- | --- | --- |
| 尚未提交的信息 | 待填写/草稿 | 补充、修改、下一步、取消草稿。 |
| 待确认原操作 | 待确认 | 核对后确认；返回修改须结束旧待办；取消本次。 |
| 待强验证 | 待身份验证 | 明确实际验证方式，验证并办理；取消本次。体验验证与手机验证不能混淆。 |
| 服务端正在处理 | 处理中 | 查询原操作；不重复提交、不暗示已完成。 |
| 结果未知/待核实 | 结果待核实 | 查询原操作与查看详情；不能直接发起替代付款。 |
| 明确已成功 | 按动作显示“转账已完成/预留已完成/申请已受理”等 | 查看明细或业务详情；不把受理、保存或派发改写成付款成功。 |
| 原操作已拒绝或安全取消 | 本次操作已取消 | 显示原因；只有确定无未决执行时才允许重新填写。 |
| 失败、过期或锁定 | 未完成，并显示具体原因 | 按原规则核实、重新验证或重新办理；只有确定未执行/已回滚时才写未扣款。 |
| 已保存的未来任务 | 预约已保存/待到期/待本人确认等 | 查看任务、合法取消或处理原执行；任务状态与付款状态分别显示。 |

状态名称统一，结果内容保持业务差异。不能把理财赎回、订阅取消或卡片受理机械改写成转账结果。

待办入口采用统一业务处理区：每项先展示对象、金额/份额、时间、状态和下一步，直接恢复并办理原操作。能在公共区完成验证时就在此完成；需要专属页面时提供明确按钮并携带原操作身份。AI发起和后台派发同样可恢复，不能只凭业务名跳转后新建请求。

## 六、预约、后台和计划的特殊处理

项目目前的预约语义是“到期准备待办，付款仍需相应授权”。页面名称可用“预约转账”，但登记前和结果页必须明确“到期需本人确认”，不能借名称暗示无人值守付款。

- 保存计划、允许该计划准备待办、后台进程实际运行是不同事实，分别展示。
- 若用户选择启用后台，在现有身份和控制机制允许时显式启动并核实；没有满足条件时显示下一步，不显示虚假运行成功。
- 若只保存未启用后台，结果明确提示；不能按钮写“启用”而实际上只保存一个标记。
- 未领取转账任务迟到超过5分钟的现有规则继续有效，在登记前给出可理解的说明。商户任务使用自身规则，不照搬转账窗口。
- 生日流程保留手动管理能力，但放到“手动管理”区域；正常用户沿一条完整计划主线操作。
- 计划暂停、删除建议、取消任务、已执行付款、释放预算分别处理；没有退款能力就不出现可用的“退款成功”流程。

## 七、AI 助手如何融入普通操作

AI用于理解目标、补齐信息和组织步骤；字段选择、核对、确认、验证和结果保持与手动办理一致。

- 缺金额就问金额，缺对象就给可信选择；同名消歧显示银行及已有尾号。
- 主区显示模型是否已配置及当前可用的替代入口。“已配置”不等于已实际连通，不自动发送付费请求测试。
- 模型供应商、接口和密钥放“我的—高级设置”，普通业务流程不要求用户理解这些配置。
- “人工接管”改为符合实际的“改为手动处理”；停下后展示可继续办理的具体入口，不虚构客服已接入。
- 暂停、继续、返回修改等控制只在对应阶段出现；先查询已受理操作，再决定如何继续。
- 已完成计划步骤使用实际进度，不能在另一块计划表里一律写“尚未执行”。

## 八、实施优先级与交付

这些是产品交付目标和验收顺序，不预先指定委派内部怎么编码或拆任务。正式实施按AGENTS把完整目标一次交给DeepSeek原会话完成，Codex独立审查并修正收尾缺陷。

| 优先级 | 交付目标 | 覆盖审查项 |
| --- | --- | --- |
| 1 | 金额单位、身份、公共状态、待办恢复统一，确保用户知道钱与权限的当前事实 | UX-01、02、03、04。 |
| 2 | 导航与名称统一；直接转账表单、核对/修改/取消、可信中文摘要、AI共用办理流程 | UX-05、06、07、08。 |
| 3 | 预约、后台、生日与理财形成连续流程；手动接管和问卷交互合理 | UX-09、10、11、12；补齐订阅说明。 |
| 4 | 完整用户走查、旧业务回归、数据兼容与使用说明 | 覆盖全部审查项及关键异常路径。 |

预期交付：可运行的隔离预览、完整改动清单、独立验收证据、简短用户操作说明。沿用现有依赖、资金与授权服务；不添加真实银行接入、真实卡开户、短信/刷脸、新收费规则或长期免密支付。

开工前重新核对本地版本、未提交改动、原委派会话与累计成果；有版本变化按既定规则处理，不静默替换会话或丢弃并行改动。验收使用独立库，不复制日常凭据或重置本机业务数据。整合和发布按届时明确授权执行，不把方案文档视为提交或推送指令。

## 九、验收标准

| 用户任务/边界 | 必须满足的结果 |
| --- | --- |
| 第一次打开 | 能明确判断体验还是登录；设置流程不遮挡主导航；初始化后没有体验绕过入口。 |
| 200.01元全链路 | 手动/AI/预约/预算等相关金额全用元；请求精确为20001分；不接受三位小数后自动舍入。零值只在原业务允许时可用。 |
| 同名对象 | 显示可信银行/尾号并由用户选择，不根据姓名猜ID，不凭空编造账户信息。 |
| 手动与AI办理 | 相同动作的摘要、授权要求、最终结果一致，不产生两笔重复业务。 |
| 核对页改金额/对象 | 旧待办安全结束后再核对新信息，旧验证码/授权不可批准修改后的内容。未知结果不允许借修改重发。 |
| 重复点击/刷新/重登 | 不重复扣款、不丢已受理操作，登录不自动批准付款，能恢复原对象、金额和备注。 |
| 手机验证 | 已绑定模式显示真实所需验证方式；错码、过期、重放、锁定都有正确提示；不降级到体验验证。本人设备签收单列。 |
| 取消与未知结果 | 不把关闭页面、停止后台或取消草稿当成撤销付款。超时不冒充失败未扣款。 |
| 预约 | 保存后准确展示后台状态、本人待确认与原失效条件；派发不等于付款。 |
| 生日计划 | 保存后同一入口可见进度和待办；预算、订单及剩余释放与实际账本一致。 |
| 卡片/AA/订阅 | 中文状态和元金额；卡状态影响如实展示；AA不冒充已收款；订阅查询继续按题目yellow确认，不削弱契约。 |
