## 使用方法

在项目根目录打开Windows PowerShell，继续使用现有虚拟环境。安装新增依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-app.txt -r requirements-materials.txt
```

页面仍使用原启动方式。手机验证要先在本机初始化一次账号：

```powershell
.\.venv\Scripts\python.exe -m bank.auth
```

在这个**本机终端**输入用户名和新密码（12—256字符）。程序只允许首次受控初始化，不能覆盖已有身份。初始化会显示8枚一次性恢复码，立即离线保管；不要提交、发到聊天或让AI代填。此操作会将原模拟用户A的账户与本机登录身份关联，之后所有银行业务入口要求登录和绑定手机。

刷新页面→输入刚建立的账号密码→手机验证器扫描页面上的二维码→在本机页面输入手机当前动态码完成绑定。绑定用过的码不能再授权交易，请等待手机下一枚动态码。密钥用当前Windows用户DPAPI加密保存；当前真实绑定模式面向Windows，不宣称Linux机器已具备该加密能力。

丢手机时，在登录页展开恢复入口，使用账号密码及一枚未使用的恢复码撤销旧会话、清除旧绑定后重新登录绑定。恢复不会批准交易，旧交易证明同时失效。没有恢复材料时，不提供删除配置文件绕过验证的后门。

后台在**另一个终端**运行：

```powershell
.\.venv\Scripts\python.exe -m bank.worker
```

每5秒检查一次；Ctrl+C停止。关闭网页不会停止该工作进程；关闭后台终端、电脑关机或休眠会影响执行。没有安装开机自启或云服务，也没有在本轮擅自启动日常后台。到期黄色/红色业务进入待确认/待验证，不自动付款。

AI银行助手新增“恢复完整计划”和“后台任务与通知”。后台推进普通AI计划需点击“允许后台准备后续待办”；只保存草稿不会自动授权付款。后台通知是持久站内待办，查看/已读独立记录；本轮未实现Windows弹窗、短信或邮箱送达，不将写入数据库说成外部通知已送达。

生日页面展开“保存完整生日计划并由后台准备到期待办”，核对预算、商品、地址、预算处理日期及提前两天采购时刻后保存。到期后在AI助手恢复该计划，按步骤完成确认与验证。若某笔未获授权、失败或结果未知，后续依赖不继续；暂停与未完成状态可恢复。月初生日如与“当月才预留”冲突，会明确拒绝该时间组合，需用户重新选择/明确规则，不偷改日期。

## 技术与接口变化

- 默认/演示请求继续使用v1.1，原样例保持兼容；新增支持v1.2交易请求与授权，仅v1.2允许待验证回执标记`methods=["totp"]`。模型仍不提供身份或验证证明。共享上下文、内部资金与任务外层契约维持既有版本，嵌套业务请求可以是受支持的v1.2。
- 实际银行账本仍为模拟业务。初始化本机身份后，网关动态检测真实模式，拒绝演示凭据；旧页面缓存不能继续按模拟模式授权。会话过期、退出或恢复后不再放行，验证证明还绑定签发时的登录会话。
- 密码采用独立盐的scrypt；登录失败与TOTP失败分别计数，成功密码登录不能清除TOTP锁定。TOTP使用PyOTP 2.10.0（MIT），本机二维码使用qrcode 8.2（BSD），均固定在依赖清单。动态码不进日志、模型或计划快照。
- 存储增量升至v15，保留v13及较早版本数据；包含对开发期间v14结构的兼容。迁移与版本号同事务提交，不重置余额、流水或授权记录。迁移失败回滚，不删除运行库“解决”错误。
- 持久计划在执行前保存请求及操作键；银行提交后进程退出，恢复先查询原结果。查无记录时也不能推定未付款，只能在网关幂等保护下重投同一请求、同一键，不生成替代键。
- 定时登记与实际付款分开。依赖付款成功的后续步骤等待真实模拟执行回执，不能仅凭`scheduled`提前推进。失败、过期、暂停与未知结果均保留事实。
- 后台以SQLite租约控制活跃实例，崩溃后通过租约到期和原键恢复；任务执行与通知的幂等键独立，补通知不会重做付款。后台不调用模型、不持有批准付款能力。
- 静态C资料页继续独立读取随仓库分发的虚构样本，不打开运行账本；它明确不是已登录用户账户。所有当前银行业务页、模型设置及恢复入口进入真实模式后需认证。
