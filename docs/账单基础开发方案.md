## 1. 本批目标和范围

用户能选择自己的账户及月份、年份或日期范围，看到该期间的消费/订阅毛支出、分类汇总和图表，以及退款说明。查询不改变余额或流水，也不干扰已有转账、授权与恢复。

可以使用明确标记的独立模拟数据开发和测试；不得自行补造 C1 的账户映射、消费分类、交易时刻或异常判定规则。C1 原 Excel 位于仓库外的群组资料目录，本方案不将它视为已导入项目的数据。

本批只交付账单基础统计。正式 C1 导入、基于 C 的独立手算验收和自动异常检测分别受 C1-001、C1-002、C1-003 限制；基础代码完成不会自动解除这些记录。六场景自然语言路由留在 2.3，本批先提供明确的账户/日期查询入口。

## 3. 已确定的接口和计算规则

- 继续使用 `bill.analyze`，输入只有既定的 `account_id`、`start_date`、`end_date`。月份和年份由页面转换为日期范围，不增加公开接口字段。
- 继续返回 `total_expense_minor`、`categories`、`anomalies`、`report`；所有金额计算用整数分。共享接口和模块边界不因本批开发改变。
- 毛支出统计期间内消费和订阅的已记账出账；收入、转账、理财和退款不计入。分类使用流水已有的 category，不能从商户名或 C1 的支付渠道猜分类。
- 退款按本期退款记录单独说明，不推测退款原订单或归属月份，不扣减毛支出。年费按实际扣费记录计入当期，不自行摊销。
- 按上海日期解释查询区间，两端均包含。若使用分页查询必须遍历完整快照；如果复用内部读取，应保证与现有流水筛选口径相同，并在一致的读取视图中生成总额、分类和报告。
- 聚合金额超过现有安全整数范围时按既有错误码失败，不截断、不转成浮点数。
- 异常规则未确认时，`anomalies` 保持空列表，`report` 和页面同时明确“自动异常检测尚未启用，空列表不代表没有异常”。基础统计成功只代表查询与统计完成，不代表完成异常审查。不新增自创的状态或字段表达局部能力。
- 页面可展示正常运行库的真实模拟流水；为了演示消费分类而构造的数据必须放在隔离的临时库/测试样例，不能通过普通账单查询向日常银行插入流水。现有账户只有转账时，账单毛支出为 0 是正确结果。

## 4. 可直接开始的验证样例

下面是独立工程测试样例，不来自 C1 原表，不作为 C 已交付的手算材料。

| 记录 | 金额 | 类型/方向 | 已明确分类 | 是否计入毛支出 |
|---|---:|---|---|---|
| 样例消费 | 100.00 元 | consumption / debit | 餐饮 | 是 |
| 样例订阅 | 20.00 元 | subscription / debit | 影音会员 | 是 |
| 样例转账 | 200.00 元 | transfer / debit | 转账 | 否 |
| 样例退款 | 30.00 元 | refund / credit | 退款 | 否，另列 |

预期：毛支出 12000 分；餐饮 10000 分、影音会员 2000 分；退款说明 3000 分。不能得到 320 元的毛支出，也不能用退款冲减为 90 元。测试加载已记账历史时，应配套开账余额与入/出账校验，不绕过统一资金边界开放任意充值功能。

基础验收至少覆盖：

1. 上述混合交易口径，以及收入、理财排除。
2. 不同账户隔离、其他用户越权拒绝。
3. 空账户/空期间、全年和跨月范围、上海月末月初。
4. 超过 100 条流水不漏算、同一次读取总额与分类一致。
5. 非法日期、金额溢出、后端失败与坏回执不能显示成功。
6. 页面金额、表格、图表一致；未检测异常不显示“无异常”。
7. 查询前后余额、流水、授权挑战和业务操作记录不变。
8. 现有转账、确认、模拟验证、恢复和重复执行防护不回归。
