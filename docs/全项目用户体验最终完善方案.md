## 1. 产品目标与赛题边界

目标是让人用自然语言顺利办理模拟银行业务：说出需求，补齐必要信息，按风险确认或验证，得到可信结果，并在异常后继续处理。熟悉的银行表单作为手动办理入口。界面简洁与安全控制同时成立。

本次重新查看了仓库保存的三张赛题原图：[背景与六场景](../项目要求-非代码/屏幕截图%202026-10-10%20194624.png)、[权限、安全与任务规划](../项目要求-非代码/屏幕截图%202026-10-10%20194644.png)、[交付要求](../项目要求-非代码/屏幕截图%202026-10-10%20194654.png)。以下结论只针对这三张原始资料。

| 赛题要求 | 最终体验应体现的行为 |
| --- | --- |
| 自然语言理解、模糊表达和上下文 | 缺什么问什么，展示连续的助手追问与用户回答；选择对象使用可信名称，用户不必填写内部编号。 |
| 至少三个场景，鼓励全部覆盖 | 保留当前全部六场景，逐个验收；预算、AA、预约、产品对比等已有配套功能也纳入走查。 |
| 绿色自动执行 | 余额、交易记录、账单分析等现有纯查询直接返回结果，不增加无意义确认。不能因另一条普通待确认事项禁掉阅读与提问。 |
| 黄色明确确认 | 保留小额转账及订阅查询/取消等确认要求；原图明确将订阅查询列为黄色，不能为减少点击擅自改成绿色。 |
| 红色强验证 | 保留大额转账、卡片挂失/解挂、理财申购等强验证路径。演示验证与真实本机验证清楚标识；演示按钮不能作为真实强验证通过的证据。 |
| 幻觉防护、注入防御、审计和熔断 | 账户和结果来自可信服务，模型只提出需求与计划；不通过简化页面绕过鉴权、金额复验、幂等、原操作核实和失败锁定。 |
| 任务分解、暂停、回退与人工接管 | 一份可读的任务进度，明确当前步骤和下一步；暂停停止后续推进，不能宣称撤回已提交业务。 |

三张原图没有规定第一次进入必须绑定个人手机号或开真实银行账户。当前已提供“体验示例账户／设置本机账号”，应保留这项改善；已初始化本机身份仍须遵守原登录及绑定保护，不能借体验模式降级。项目采用密码和手机动态码实现自己的强验证路径，具体能力按实际测试记录说明。

## 2. 本轮核查结果

本轮检查当前全部页面脚本及共享交互、AI、认证、权限和恢复路径，并核对最新验收与交付材料。独立临时副本中实际查看了欢迎页、首页和卡片页；没有调用付费模型，也没有操作日常账本或个人验证器。

当前主目录已有的验收记录为659项回归和5项干净启动/后台检查。核验初期，其157个源码、测试和脚本哈希与当时文件一致；核验期间，其他AI又更新了8个权限展示相关源码文件，旧回归证据不能直接覆盖这批新改动。这是版本核对，不是本轮重新执行659项。旧浏览器证据没有覆盖当前所有按钮和全部页面的窄屏状态，旧97按钮统计不能当成本轮总数。

两项连续操作问题已用临时账本实际复现：生日手动预留切页后，原操作仍待确认而处理入口消失；订阅核实成功后，列表和继续管理入口仍消失。AI暂停/接管后的静默忽略及客户端配置错误残留也做了纯内存探测。审查证据见[本轮记录](evidence/ux-final-review-20261028/review.json)，复现成功表示问题存在，不表示问题已经修好。

已经改善并应保留：主区欢迎选择和设置向导、“我的”集中设置、元与分的精确转换、风险问卷不预填答案、产品选择带入申购、生日完整计划持久恢复、公共待办真实验证入口，以及对结果未知操作的保护。

## 4. 冲突与安全边界

先解除整页冻结，再在实际提交处做有依据的限制。普通解释、澄清、页面浏览和未提交草稿不占用原付款请求；现有纯只读查询保留身份与资源归属检查。

不能把所有绿色动作当成无副作用查询，例如风险评估会持久化；不能把订阅查询当成无需授权。现有日累计、授权时效、失败锁定、资源版本复验、卡片状态机及预留占用规则继续沿用。

同一未知付款的替代提交、改金额/对象后重新付款，以及受未知订单资金占用影响的释放/消费继续保护。查无记录不等于未执行，刷新、新需求和退出不替代核实。安全只读分支不得覆盖原未知请求、原键、摘要或恢复标记。

对不同写操作，只有现有契约和可信资源状态足以判定互不冲突时才允许继续；无法判定时在提交处指出关联的原待办并提供处理入口，不无条件放开任意并行写。若实施中确有无法据现有材料决定的业务选择，记录 BLOCKERS，其余功能继续推进。

## 5. 画面收口标准

- 首页首屏突出账户概览、AI需求入口与少量常用服务；有待办时可直接看见待处理提示及入口，不把整块界面锁住。
- AI页面以对话和当前任务为主，一份计划即可；后台、原始回执、模型元信息和技术编号按需展开。
- 业务页依次呈现对象/输入、核对、按级别确认或验证、结果；只读业务用短流程。确认按钮写明动作和必要金额，取消说明实际影响。
- 每个当前步骤只突出一个主动作。隐藏不适用的操作或禁用并说明条件；保留可返回、取消和核实的路径。
- 不堆积重复导航、边框卡片、长条提示和开发说明；必要限制放在作决定之前，帮助与技术细节放展开区。
- 沿用现有浅色、深色文字和克制的强调色，不更换前端框架、不新加装饰依赖；优先原生布局与主题。
- 状态同时有中文文本，颜色只辅助表达；金额使用元和两位小数，内部保留整数分，份额与日期明确标注。
- 桌面、390px窄屏与200%缩放下，正文、校验信息、确认/验证和返回入口可读可达；主要办理流程不靠横向滚动。

## 6. 最终验收与实施方式

### 6.1 验收矩阵

建立本版页面与控件清单，包含：首页四个子视图、11个子页，以及登录/恢复、公共待办、模型设置、后台和退出的共享控件。只统计当前版本，不继承旧按钮数量。

每个主动作要覆盖正常结果或该动作的合法终点，以及适用的取消/拒绝路径；每个禁用状态要有原因与可达去向。页面无异常、按钮存在、测试数量增加，均不能单独当作体验通过。
