## 明确的手算答案

| empty，2026 全年 | 无 | 0 / 0 | 空列表 | 0 |
| b，由 b0_user_b 查询 8 月 | 12 | 500.00 / 50000 | 日用百货 500 | 0 |

`b0_user_a` 查询 b 账户的预期是 FORBIDDEN，不能把 b 的 500 元消费合并进 a 的账单。此处仅准备预期，实际账单网关权限验收在 B2 执行。

余额对照：

- a 入账：30+500+10+1=541 元；出账：100+20+200+50+7+9=386 元；期末 1000+541−386=1155 元。
- b 入账 200 元、出账 500 元；期末 1000+200−500=700 元。
- empty 无流水，期末仍为 500 元。每个账户的按时间顺序中间余额也不得为负。

这些余额是历史对账答案，不是账单毛支出。退款不冲减毛支出，理财入账不假定为收益，消费分类不从商户名猜测。异常阈值和异常结论均未提供；不得把样例中没有异常结果解释成已检测无异常。

## B1 统计核心（2026-10-14）

实现位置：[billing/__init__.py](../billing/__init__.py)。内部调用 `from billing import analyze`，再执行 `data = analyze(params, transactions)`；params 使用既有 bill.analyze 三个字段，transactions 是完整一致快照的标准流水迭代对象。返回既有四字段 data，可由共享适配器包装为结果。此函数不接收用户身份、不负责账户授权；不能直接作为对外入口。B2 必须先检查归属，并保证读取完整快照，不能只传一页。

计算按上海日期闭区间与账户筛选，以整数分累加消费/订阅出账，分类沿用原值并稳定排序；退款入账在 report 另列，不扣减毛支出，不推断原订单。年费按实际扣费日计入；异常列表为空且报告明确未开启自动异常检测。

非法参数返回内部 ServiceError / INVALID_REQUEST；缺字段、坏金额、无时区时间、重复流水等拒绝为 UPSTREAM_ERROR。总额、退款金额超过安全整数，分类超过共享接口的 100 项容量或输出 JSON 超限，返回 LIMIT_EXCEEDED，不截断、不返回部分成功。流水条数本身没有 100 条限制；251 条迭代输入已验证。
