## A：本体收口与文档

前置：C-07 影响 R01 与 R03-B，不影响 N4；E-11 只影响年付识别边界；E-02 的 `card_id` 由 A 统一评估。接口按以下结论落地：`merchant.order` 增加**可选** `card_id`（向后兼容），错误码优先复用现有 `INVALID_STATE`/`LIMIT_EXCEEDED`，`application.cancel` 本轮暂缓。

1. **商户链路（N4 核心）**：`merchant.order` 接入选卡与执行前复验、`consume_reserved`、部分消费后 `closed` 与剩余释放、订单级可信未执行证明、与迟到提交互斥、取消商户任务后释放。未知结果一律原键查询，不猜余额、不自动释放。
2. **生日链路与 `scenario.plan` 运行时**：计划只生成 DAG 不扣款；`budget.reserve` 另行确认；逐笔下单、配送日约束、中断/unknown/人工接管三条流程按 E 的预期实现。
3. **订阅取消与提醒**：实现 `subscription.cancel`、`subscription.remind`，取消后未触发提醒作废、已派发任务执行前校验；取消后停止模拟扣费的验证方法按 E-001。
4. **六场景路由**：自然语言到动作的最小可用映射，至少覆盖转账、账单、理财（待 D）、卡片、订阅、生日联动；不猜账号、不越权。
5. **文档与答辩**：技术文档（架构/调用链/安全设计）、安全自评报告（权限分级、已知风险）、答辩 PPT 提纲与讲稿。

验收：每项独立验收文档与证据；全量测试通过、日常库不变；六场景端到端演示可在临时库复现；未实现分支写“待开发”，缺规则写“阻塞”。
