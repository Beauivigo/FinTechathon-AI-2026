## A：本体收口

前置：C-07 影响 R01 与 R03-B，不影响 N4；E-11 只影响年付识别边界；E-02 的 `card_id` 由 A 统一评估。接口按以下结论落地：`merchant.order` 增加**可选** `card_id`（向后兼容），错误码优先复用现有 `INVALID_STATE`/`LIMIT_EXCEEDED`，`application.cancel` 本轮暂缓。

1. **商户链路（N4 核心）**：`merchant.order` 接入选卡与执行前复验、`consume_reserved`、部分消费后 `closed` 与剩余释放、订单级可信未执行证明、与迟到提交互斥、取消商户任务后释放。未知结果一律原键查询，不猜余额、不自动释放。
2. **生日链路与 `scenario.plan` 运行时**：计划只生成 DAG 不扣款；`budget.reserve` 另行确认；逐笔下单、配送日约束、中断/unknown/人工接管三条流程按 E 的预期实现。
3. **订阅取消与提醒**：实现 `subscription.cancel`、`subscription.remind`，取消后未触发提醒作废、已派发任务执行前校验；取消后停止模拟扣费的验证方法按 E-001。
4. **六场景路由**：自然语言到动作的最小可用映射，至少覆盖转账、账单、理财（待 D）、卡片、订阅、生日联动；不猜账号、不越权。
5. **（截止较晚，不占本轮关键路径）文档与答辩**：技术文档、安全自评报告、答辩 PPT 与讲稿排到本体可运行后的后续轮次；本轮只在实现时顺手留证据，不专门写。

验收：本体可启动、已实现场景端到端可演示、全量测试通过、日常库不变；每项功能有验收文档与证据；未实现分支写“待开发”，缺规则写“阻塞”。文档类不参与本轮验收。

## D：三轮折一天交付

前两轮未交；按“一轮一天”的口径，D 拖欠的三轮**折算为一天（10-19 内一次交齐）**，A 仍按三个包分别验收，不因压缩时间降低标准。

1. **第一包（同日交）**：5—8 个虚构产品（ID、风险、期限、起购、净值/费用口径）、完整问卷（题目、分值、总分、档位边界、漏答处理）、申购/赎回规则（价格时点、费用、份额精度、锁定、到账），以及正常申购、正常赎回、风险不匹配、起购不足、不可赎回五类算例。
2. **第二包（同日交）**：用同版产品完成“问卷→对比→申购→持有→赎回→到账”完整故事与逐步预期；补拒绝、重复、unknown、锁定边界、份额不足；交对账表。
3. **第三包（同日交，讲稿可后置）**：完整理财演示脚本（含失败与中断分支）；3 分钟答辩讲稿可后补，不阻塞本体。

验收：A 可仅凭资料手算评分与申赎；风险边界无空档或重叠；演示脚本逐步可复算。三个包分别登记通过情况，不能用一个包的通过代替另外两个。

3. 生日三条流程的最终文案与页面走查：配合 A 的 N4，确认计划/预留/下单/unknown/中断各停止位置。
4. 订阅取消、提醒、申请换键的边界算例：每条给前置、结果、重复操作与边界预期；取消后“停止模拟扣费”的验证口径。

验收：确认项有明确结论；文案可直接用于页面；边界算例可执行；不把“登记/计划”写成“已执行”。
