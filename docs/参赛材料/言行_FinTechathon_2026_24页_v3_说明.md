## 2. 第 13 页：理财（内容重做）

原页面只列出 R1—R5 与「R2 ≠ R4」，未说明档位来源，且适配规则表述不准确：允许申购的条件是用户档位不低于产品档位，而非两者相等。

| 项目 | 原稿 | 修订后 |
| --- | --- | --- |
| 适配规则 | `R2 ≠ R4` → 拒绝 | 允许：用户档位 ≥ 产品档位；拒绝：用户档位 < 产品档位，不进入确认/强验证、不扣款 |
| 档位来源 | 无 | 问卷 5 题 × 1—4 分 → 总分 5—20 → R1 5—8 / R2 9—12 / R3 13—16 / R4 17—18 / R5 19—20 |
| 费用与份额 | 「费用到分；份额 4 位；0.5 分进位」 | 可复算算例：500 元 → 费 50 分 → 份额 499.5；脚注「0.5 分进位 · 份额 4 位」 |
| 边界 | 6 个虚构产品；静态净值；模拟 T+1 | 同上，脚注补「不承诺收益」 |

依据为 D 第一轮规则 §2.3（档位映射）、§2.4（适当性）、§3.2（申购公式）、§3.3（赎回公式）。

实测（网关层，独立临时库）：50000 分申购 WP-C02，`fee_minor=50`、订单份额 `499.5`、持仓 `499.5000`、余额 200000 → 150000；锁定期内赎回与份额超限均在确认前返回 `INVALID_STATE`，验证挑战数不增加。复现脚本 `verify_d_flow.py`。

## 3. 第 21 页：展示 UI（截图替换）

原图为旧版界面（橙色左侧导航、扁平白卡片），与页面标注「实际安装 2.0.0」不一致。

替换为 2.0.0 柔彩界面的实机截图，画面包含：授权级别 红色 · 强验证、验证方式 体验模拟验证、执行状态 已完成、转账金额 ¥1,200.00、收款人 李明。

抓取方式：无头 Edge 驱动本机 2.0.0 页面，走「体验示例账户 → 转账与收款 → 收款人 → 金额 1200 → 核对 → 体验验证 → 结果页」，1280×720 视口截图，顶部裁切 36 px。截图前备份 `runtime/sandbox.sqlite3`，截图后还原并重启服务，演示账本未留下该笔交易。

## 4. 全篇文案（54 处）

处理原则：

1. 删除「不是 X，而是 Y」「缺的是」「才」「越……越……」等对照与修辞句式，改为事实陈述；
2. 标题改为名词化陈述或事实判断（现状 / 定位 / 架构 / 交付范围），不再使用比喻（大脑、笼子、孤岛、信任链）；
3. 保留技术事实与术语：TOTP、unknown、幂等、绿黄红、1000 元门槛、713 项等；
4. 长度控制在原文本框容量内，字号与位置不变。

明细见文末对照表。
