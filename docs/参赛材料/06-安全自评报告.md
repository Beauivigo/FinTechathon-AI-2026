# 银行 AI 智能体安全自评报告

材料版本：v0.1，2026-10-23。编写者：A / Codex。适用范围：Windows本地模拟银行、固定演示身份、虚构数据和模拟强验证。该报告依据源码与项目内验收记录整理，属于项目自评，不是第三方渗透测试、生产认证或银行合规结论。

版本基线及当前文件哈希见[材料检查记录](材料检查记录.json)；系统架构与业务范围见[技术文档](02-技术文档.md)。

## 1. 评估对象与信任边界

评估资产包括模拟账户、余额及预留、流水、订单、卡片状态、订阅、理财档案和持仓、授权挑战、模型密钥与审计记录。

用户自然语言、模型JSON、商户名称和订阅依据均作为不可信输入。可信程序负责业务编译、身份选择、对象归属、权限计算、授权和入账。模型没有主机文件、命令、SQL执行或内部资金工具；模型输出的“已成功”“已确认”不会获得交易授权。

当前演示身份由页面和可信调用方提供，没有真实登录认证。归属检查能够约束既定身份下的请求，但不能据此宣称具备生产多用户身份体系。

## 2. 权限分级实现

下表依据[共享契约](../../shared/contracts.py)和[权限计算](../../shared/policy.py)。定时登记与到期实际付款分开处理，不能将登记授权继承为付款授权。

| 等级 | 当前动作 | 执行条件与说明 |
|---|---|---|
| 绿色 | 余额、收款人解析、流水、原操作查询、账单分析、产品对比、生日日期计划 | 仍检查输入与归属；允许范围内的纯查询不需二次确认 |
| 绿色 | 风险评估`wealth.assess` | 由用户提供完整问卷；保存档案是幂等写操作，绿色不等于无状态；AI入口仍要求显式准备 |
| 黄色 | 含本次日累计≤1000元的转账、AA收款单、卡片申请受理、订阅查看/识别/核实/排除/取消/提醒、预算预留/释放 | 展示具体对象和内容并获得确认；订阅查询也按既定契约列为黄色 |
| 红色 | 含本次日累计>1000元的转账、理财申购/赎回、卡片限额/冻结/解冻/挂失/解挂、商户下单、每期订阅续费 | 必须经过模拟强验证；卡片部分动作采用较保守的红色分级 |
| 动态 | 定时转账登记及到期执行 | 按既定流程计算登记要求；到期手动检查，执行时重新计算累计并重新授权 |

转账累计使用同一用户跨付款账户的上海执行日数据，并处理并发占用与执行前变化。门槛为100000分，含本次等于门槛仍为黄色，超过门槛为红色。

授权摘要绑定版本、用户、动作、规范化参数和幂等键。挑战有效期10分钟；普通确认不能满足强验证，凭证需有效、匹配且未使用。错误凭证累计5次锁定本次操作，页面重开不能解除服务端锁定。模型会话连续5次异常草稿是另一机制，用户核实后可重开需求；它不能解除银行操作锁定或清除未知结果。

依据：[网关](../../bank/gateway.py)、[会话控制](../../agent/controller.py)、[授权与恢复测试](../../tests/test_gateway.py)、[最终页面验收](../../tests/test_closeout_acceptance.py)。

| 幻觉交易结果 | 模型只提出草稿，页面以网关实际回执更新状态，缺信息须补充 | 六场景页面与真实模型分组；不将模型回复当账本事实 |
| 重复点击、刷新和回执丢失 | 幂等键、参数摘要、原键查询、未知结果阻断后续 | [恢复测试](../../tests/test_recovery.py)、最终页面丢回执用例；不以超时或查无记录推断未执行 |
| 越权或授权期间状态变化 | 服务端身份与归属、执行前重验；检查余额、卡状态/限额、产品风险、锁定期等 | 网关、卡片、理财、商户及并发测试；并不替代真实登录认证 |
| 部分写入与金额不守恒 | 整数分、Decimal、事务及保存点，关联订单、账本、结果与审计 | 资金、预算、商户、理财回滚与并发用例；实际模拟范围有证据 |
| 超大或非法模型响应 | 限长、限深、节点及任务数上限、重复键拒绝、超时、无自动重试 | 模型传输及安全测试；没有完整服务级配额与防拒绝服务能力 |
| 连续异常或审计不可用 | 连续5次无效草稿熔断；审计失败停止新推进；已入账事实保留 | 模型锁定、审计故障、页面持久锁定用例；不是持续主动安全告警系统 |

上述断言对应[安全及六场景报告](../2026-10-23安全收口与六场景最终验收.md)的G01—G15矩阵，不将测试通过扩大为系统无漏洞。

## 4. 隔离与审计

### 4.1 声明式计划的逻辑隔离

模型只能提供有界JSON计划，可信编译器将允许的意图映射为固定业务动作。身份和授权来自可信代码，资源归属在服务端重验。模型不能选择任意文件、主机命令、外部工具或内部资金入口。脚本字符串即使出现在说明文字中，也没有代码执行路径。

已验证边界为声明式计划的逻辑隔离。当前没有独立OS沙箱、容器、主机文件ACL隔离或防本机管理员篡改能力，也不支持任意模型生成代码的安全运行。模型安全用例验证了注入没有获得文件、命令或额外银行权限，不能据此推导主机完全隔离。

赛题依据为[技术要求原截图](../../项目要求-非代码/屏幕截图%202026-10-10%20194644.png)。当前方案与证据供评审判断，不宣称已取得主办方对隔离方案的正式认可。

### 4.2 审计范围

可信程序生成`plan_…`跟踪号，关联模型请求、草稿接受或拒绝、暂停/继续/回退/接管/重开、执行步骤及银行事件。计划事件仅保存允许的技术元数据，不保存提示原文、模型自由文案、密钥、验证码或验证令牌。

审计不可用时停止新的模型推进；银行操作已提交时仍保留实际结果并阻止后续依赖，不能将已扣款写成未执行。审计位于同一SQLite数据库，没有独立的不可篡改存储或主动告警渠道。本机有文件权限的人可能修改或替换数据库，属于剩余风险。

依据：[模型事件入口](../../bank/gateway.py)、[计划状态](../../agent/model_dialogue.py)、[执行审计](../../agent/model_bank.py)。

## 5. 模型服务、密钥与数据

模型客户端仅允许代码规定的DeepSeek官方HTTPS地址或本机HTTP回环地址，禁止重定向；对本机地址不自动沿用官方备用密钥。默认请求超时45秒，无自动付费重试，传输与模型错误向用户返回经过控制的提示。

银行独立密钥可以通过环境变量或配置提供；Windows本机保存模式采用当前用户DPAPI加密，页面密码输入不回显。用户也可显式选择沿用本机桌宠凭证，该可选路径依赖本机桌宠环境，不能作为交付包的必需条件。

DPAPI不能防止已控制当前Windows账号的程序获取密钥。环境变量和自行提供的配置也不等同于加密保险库。密钥不进入模型提示词或项目日志，运行库、私密配置和本机凭证不应进入源码交付包；本次文档检查仅检查新增材料，不冒称已完成全仓最终发布扫描。

官方模型请求会发送用户对话和必要的模拟业务上下文，包括账户标识、卡片状态与限额、产品、持仓、模拟商品地址及已执行步骤回执。外部服务的数据处理范围尚未作为生产个人数据场景完成审核。当前只应用虚构数据；接真实个人或金融数据前，需要另行完成字段最小化、脱敏、授权及服务方处理范围核验。

依据：[模型客户端](../../agent/model_client.py)、[凭证存储](../../agent/model_credentials.py)、[模型接入说明](../AI模型接入与验收.md)。

## 7. 验证记录及自评结论

2026-10-23保存的F1安全与授权回归为63项、F2页面接线为10项、当时完整回归为547项，均0失败、0错误、0跳过；专项已包含在完整回归中，不相加。该版本真实DeepSeek9组11次的保存结果均通过，银行和身份验证仍为模拟。

后续新版界面记录为554项完整回归，0失败、0错误、0跳过，未新增真实模型调用。本次逐文件核对，最新完整回归记录的108个源码哈希全部与当前文件一致；真实模型记录148个文件中5个界面或测试文件已变化，业务与安全核心哈希保持对应。详细差异见[材料检查记录](材料检查记录.json)。

主要证据：[安全与六场景报告](../2026-10-23安全收口与六场景最终验收.md)、[新版界面报告](../UI银行改版与引导.md)、[554项摘要](../evidence/ui-bank-20261023/full.json)、[真实模型原始记录](../evidence/2026-10-23-F12-live.json)。本次未重跑上述测试，结论仅按保存记录及当前哈希核对范围引用。

自评结论：在本地、虚构数据和已定义模拟流程内，权限分级、受控计划执行、幂等恢复、审计及锁定已有指定用例证据，可以作为参赛演示与技术说明的依据。现有证据不足以支持真实资金办理、公网生产服务、任意代码执行安全或银行生产级安全声明。最终参赛前仍需完成干净启动复现、展示材料与最终发布核对；不能据本报告宣布整个参赛交付已结束。
